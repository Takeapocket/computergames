# 阶段 4.2 Expected Risk 评测记录

更新时间：2026-05-10（含 n=1000 复跑）

## 最终结论（2026-05-10 修订版）

**修订原因**：原 n=400 grid search 报告"weight=3.0 是唯一跨过 55% 合并胜率门槛的配置"；
但与次优 weight=2.0（54.75%）只差 1 局，远小于 n=400 时 ~2.5% 的标准误。
本次在 n=1000 / direction（合并 n=2000，σ ≈ 1.1%）下重跑，结论改写如下：

1. **`greedy_risk` 仍然好于 `greedy`**：稳定地在合并胜率 53.5–53.9% 区间，比纯 `greedy` 的
   50% 期望好约 3.5–4 个百分点，远超 σ。"风险感知评估有用" 这点是稳的。
2. **没有任何 weight 跨过 55% 门槛**（n=2000 下）。原 55% 门槛 + n=400 的设定本身**容易过分**，
   一次幸运的偏差就能让一组 weight 假阳性通过。
3. **weight ∈ [1.0, 5.0] 在统计学上不可区分**（最大差距 0.25%，远小于 σ）。weight=10.0
   显著变差（合并 52.5%，下滑 ~1.4 pp）——说明权重过大时风险项压过子力/距离判断，反而退步。
4. **当前默认 `EXPECTED_RISK_WEIGHT = 3.0` 是这个无差异簇里的一员**，按"距离簇中心最近 +
   原 grid search 的工程审美"保留即可，不必改。

最终默认参数（保留不动）：

```text
expected_risk_weight = 3.0
expected_win_risk_weight = 500.0
```

距离加权机制：capture risk 按 `1/(distance_to_target + 1)` 加权。weight=0.5 at d=1，
weight=0.2 at d=4。避免一刀切惩罚所有暴露子。

## 关于 55% 门槛 / 后续

阶段 4.2 的强度门槛"双边合并 ≥ 55%"是**在 n=400 下**设定的。本次 n=2000 数据表明：

- 真实合并胜率约 53.8%（greedy_risk 默认配置 vs greedy）。
- 在 n=400 下，约 1/4 的随机种子组合可以让样本胜率冲过 55%，但这是噪声。
- 若严格按 n=2000 + σ ≈ 1.1% 重新设定门槛，**53% 合并 + p < 0.01 的显著性检验**更合理
  （greedy_risk 在 n=2000 下的 z 分数约 (53.8 - 50) / 1.1 ≈ 3.4，p < 0.001，强显著）。

**不修改阶段 4 整体规划**：4.2 的工程目标——"评估函数能感知短期被吃风险并在 GreedyAI 里用上"
——已经达成，且确实有可测的 +3.8 pp 增量。下一步按 `PROJECT_PHASES.md` 进入 4.3 Edge Safety
或 GUI 建议走法集成。但下次设定 4.x 门槛时**应一开始就用 n ≥ 1000 / direction**，避免再被
n=400 的噪声误导。

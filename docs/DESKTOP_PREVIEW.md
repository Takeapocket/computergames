# 爱恩斯坦棋桌面预览版 0.2

解压整个压缩包，双击 `EinsteinChess.exe`。请保留同级 `_internal` 文件夹。

## 当前可以做什么

- 自定义双方开局，选择预设，保存和载入布局；确认布局后才开始计时。
- 单盘对局与七盘四胜制；设置我方颜色、甲乙角色，显示比分并按原有流程安排先手。
- 显示双方剩余总时间和当前步用时，支持暂停、继续和悔棋；悔棋不返还已用时间。
- 录入或随机生成骰子，选择并执行 core 允许的走法。
- 后台运行当前 P14 推荐，并执行推荐走法。
- 自动保存当前棋局及整轮进度，启动时提示恢复，也可从界面手动恢复。
- 保存和读取原有单盘 GameRecord JSON，另可导出整轮已完成各盘的 MatchRecord JSON。
- 显式旧规则版本的棋谱可读；继续走子遵循现有规则版本检查。

旧 Tk 界面继续保留，入口为 `启动项目.cmd`。新版已迁移上述比赛流程；预览版测试不等于赛事方验收。

## 对局与计时

“新建对局”中选择单盘或七盘制、我方颜色及甲乙角色，并设置每方总用时（默认 240 秒）。默认计时归零只提示，由操作者依据裁判决定使用“裁判确认超时判负”；也可在新建时显式开启自动判负。双方均归零时，手动判罚会要求选择判负方。

七盘制每盘确认实际开局。我方上盘获胜时默认沿用我方实际布局；首盘或我方失利后默认使用当前所选预设。对手每盘重新录入，确认前核对双方实际摆法，不能把示例预设当作已确认的现场布局。达到四胜后整轮结束，不再进入下一盘。

暂停只停止计时，沿用旧界面的录入行为：仍可录入合法走子和请求推荐。暂停、补录、悔棋及超时判罚应服从现场裁判要求。恢复使用已保存的剩余时间和暂停状态，不扣除程序关闭期间的时间；旧棋谱缺少计时字段时无法还原当时用时。

## 数据在哪里

便携 EXE 默认把数据放在同级 `user-data`：`records` 保存棋谱，`layouts` 保存开局，`logs` 保存日志，`recovery` 保存恢复文件。首次运行自动创建，不向 `_internal` 写入数据。请解压到可写目录；也可以通过 `--data-dir "E:/我的棋谱"` 指定数据目录。

走子、悔棋、暂停和阶段变化会触发自动保存；进行中的对局（含暂停）还会约每 2 秒保存一次，出现保存错误后停止后台重试。`recovery/auto_save.json` 保存当前盘，`recovery/auto_save_match.json` 保存整轮。请一起保留这两个文件。异常退出后可恢复最近一次成功保存的状态，尚未写盘的最后少量时间或操作可能丢失。

“保存棋谱”导出当前单盘及计时，尚未结束的盘也可另存；“导出整轮”只包含已经完成的各盘。未完成的当前盘同时由恢复文件保存。不要用整轮导出文件代替当前盘的恢复文件。新建、加载和关闭时会提醒未保存状态。升级时保留自己的 `user-data`，不要用旧版本或发布包覆盖它。

保存遇到 Windows 短暂占用会进行最多三次尝试；持续失败时显示错误，可点击“重试自动保存”。终局尚未完整保存时禁止进入下一盘，以免重复计分或丢失整轮进度。损坏或不匹配的恢复文件会被拒绝并保留，不自动删除。

主界面显示本次 AI 推荐；计算期间改骰子、新建、加载或撤销后，旧计算结果会作废。推荐没有完成时不会应用猜测走法。手动模式用于研究或录入，正式比赛操作仍须遵守赛事方要求。

## 来源与兼容

本预览版继续调用现有 core、P14 默认参数、GameRecord、MatchRecord 和原有计时逻辑。无规则版本标记的旧棋谱仍按现有兼容策略读取；明确标注不匹配规则版本的棋谱只读。Python 与 Qt 运行依赖已随便携包提供，无需另装 Python。

目标平台是 Windows x64。发布包在当前开发电脑上进行移动目录、中文路径和冻结运行测试；无开发环境的独立 Windows 机器仍需后续验收。

构建信息和文件哈希见 `build-manifest.json`，依赖许可文本位于 `third-party-licenses/`。开发构建命令：在项目独立 `.venv-desktop` 安装 `requirements-desktop-build-lock.txt` 后运行 `scripts/build_desktop.py`；原研究 `.venv` 不需要安装 Qt。构建脚本要求新的输出目录，不覆盖已发布文件。

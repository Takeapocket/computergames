# 爱恩斯坦棋参赛程序项目简介

更新时间：2026-05-09

## 项目定位

本项目用于 2026 年辽宁省大学生计算机博弈大赛校内选拔赛，方向为爱恩斯坦棋离线 GUI 参赛程序。

程序目标不是命令行工具，而是比赛现场可操作的软件：操作员录入骰子和对方走法，程序校验合法性、维护局面，并逐步加入 AI 推荐、棋谱、计时和评测能力。

## 当前阶段判断

- 阶段 0：项目初始化与规则固化已基本补齐。
- 阶段 1：核心规则引擎已完成，pytest 和 smoke test 已通过。
- 阶段 2：最小 Tkinter GUI 已实现，可显示棋盘、录入骰子、选择合法走法、执行、悔棋和重置。

下一阶段按 `PROJECT_PHASES.md` 应进入阶段 3：棋谱、计时、比赛模式。

## 当前技术栈

- Python 3.11
- pytest
- tkinter 标准库 GUI
- 当前不依赖网络服务、数据库或统一平台 API

## 已有能力

- 5x5 棋盘。
- 双方 1-6 号棋子。
- 骰子点数到可动棋子的选择规则。
- 合法走法生成。
- 吃子、胜负判断、走子和撤销。
- 状态序列化和反序列化。
- 最小随机 AI。
- 最小 Tkinter GUI。

## 当前规则假设

规则细节以 `docs/RULE_ASSUMPTIONS.md` 为准。当前关键假设：

- 红方目标角为右下角。
- 蓝方目标角为左上角。
- 红方可向下、右、右下移动。
- 蓝方可向上、左、左上移动。
- 到达目标角或吃光对方棋子立即获胜。
- 未确认正式开局布局、棋谱格式、统一平台协议和无合法走法裁定。

## 开发边界

短期内不要做：

- 深度学习训练。
- 未确认协议的平台适配。
- 联网功能。
- 正式 release 打包。
- 没有 harness 数据支撑的 AI 强度结论。

新增功能应优先保持分层：

- 规则改动先进入 `core/` 并补测试。
- GUI 只展示状态和转发操作。
- 棋谱和计时进入 `record/` 与 `gui/` 的明确边界。
- 平台适配只放入 `adapters/`。

## 常用命令

```powershell
& ".venv/Scripts/python.exe" -m pytest
& ".venv/Scripts/python.exe" "scripts/smoke_test.py"
& ".venv/Scripts/python.exe" "scripts/run_gui.py"
```

## 下一步建议

阶段 3 推荐先做最小棋谱记录，再做计时：

1. `record/game_record.py`：记录每步的回合、行动方、骰子、走法、吃子信息和局面快照。
2. GUI 接入棋谱状态，悔棋时同步回退。
3. 支持保存/加载 JSON 棋谱。
4. 增加单方总时间与每步耗时。
5. 最后再整理比赛模式提示。

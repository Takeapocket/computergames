# 赛事要求与合规证据

核查日期：2026-10-18。范围：仓库保存的 2026 年辽宁省赛通知、项目规则、总则、更新版设计说明书，以及可访问的公开通知。本文不是组委会认证，也不推定其他年份或全国赛与辽宁省赛要求完全相同。

## 当前结论

**尚不能确认本项目完全符合参赛要求。** 本轮审查发现并修复了骰子映射错误；功能回归只能证明已测试行为。具体赛项的最新补充规则、现场操作许可、程序原创性、AI 辅助披露、签字材料和答辩仍需分别核实。项目当前定位仍是长期研究；本次核查不把项目自动切回参赛封版阶段。

原程序将缺失编号理解为“全局距离最近，只有等距才可二选一”，与保存的规则第 2 条示例冲突。正确语义是：对应编号存活时只选该子；否则分别选择较小一侧的最大存活编号和较大一侧的最小存活编号，两侧都存在就都可选，无须等距。4、5 号缺失且 3、6 号存活，掷出 4 必须允许 3 和 6。

当前实现版本为 `core.rules.RULES_VERSION = "einstein-nearest-sides-v2"`。旧版胜率、Elo、布局筛选、失败归因和调参结果保留作历史记录，不再作为当前规则下的棋力证据。P14 参数与 `release/v1.0/` 配置保留，但当前代码运行这些参数时已采用修正后的规则，不能称为旧行为的逐步复现。

## 逐项核对

| 要求 | 代码/资料对应位置 | 当前判断 |
|---|---|---|
| 5×5、双方各 6 子、方向、合法自吃、到角/全灭胜 | `core/rules.py`、`core/game_state.py`、规则与状态测试 | 有实现和自动回归 |
| 骰子对应号缺失时可选两侧最近号 | `legal_piece_ids_for_dice()`、官方示例和存活集合穷举测试 | 本轮修复的关键不符项 |
| 先胜 4 盘；甲 1/4/5、乙 2/3/6/7 先手 | `record/match_record.py`、`gui/match_mode.py`、S2 演练 | 有实现和流程回归 |
| 每方 4 分钟、超时判负 | `gui/timer_panel.py`，默认 240 秒；可配置 600 秒 | 默认提示并由裁判确认，可显式启用自动判负；实际计时口径需现场确认 |
| 对弈无和棋 | core 终局只有胜负 | harness 的 `max_turns` 截断不得作为正式赛果 |
| 离线部署与平台协议 | 默认 GUI/core/AI 不依赖网络；`adapters/` 无协议实现 | 支持本地离线能力；若指定线上平台仍有适配缺口，不能宣称所有场次禁网或都无平台 |
| 程序产生我方棋步、操作员只执行许可操作 | GUI 同时保留研究用任意合法步、改骰、悔棋、暂停、恢复 | 不是强制约束的赛事客户端；正式比赛我方应执行程序输出，修正/暂停/恢复须裁判许可，不能由人临场替代 AI 选步 |
| 崩溃判罚 | 自动保存与恢复 | 恢复仅保留数据，不免除崩溃判负；由裁判决定能否继续 |
| 设计说明、源码、PPT、签字 PDF、纸质材料 | 原始通知、更新版 Word 模板、`THIRD_PARTY_NOTICES.md` | 现有模板仍待填；本次没有验证完整提交包、签名或提交回执 |
| 自行研发、参考来源、AI 辅助与个人贡献 | 项目参考资料、本次变更记录、更新版 Word 第三节 | 必须如实补充证据；Git 作者、测试通过、MIT 声明均不能独立证明人工贡献或合规 |

## 再次参赛前必须完成

1. 保存目标赛事、年份、组别的完整细则及补充通知，确认骰子、时限、网络/平台、允许的人机操作和 AI 辅助要求。
2. 在修正规则下重新评测 P14 与候选；使用新实验目录及规则版本，检查非法步、异常、超时、累计用时与双边结果。
3. 在实际比赛电脑完成 GUI 全流程、离线启动、保存失败、崩溃恢复和整轮计时演练。当前自动测试不替代现场验收。
4. 按真实开发过程补齐程序历程、参考来源、AI 生成范围、本人设计/修改/验证贡献及代码讲解材料；保留证据，不虚构贡献比例、签名或批准。
5. 准备与实际提交代码一致的说明书、PPT、依赖与运行包，按赛事要求取得指导教师确认并提交。

`scripts/preflight_check.py` 的 `READY FOR MATCH` 只代表该脚本的本地检查通过，不代表上述事项全部满足。
